# ورود با گوگل و ایمیل خوش‌آمد

دو تا کار که فقط از حساب خودت انجام می‌شود. کد هر دو نوشته شده — فقط متغیرها را
می‌خواهد.

بعد از هر تغییر متغیر، لیارا خودش برنامه را ری‌استارت می‌کند. توی لاگ نگاه کن:
اگر چیزی تنظیم نشده باشد، خود برنامه در همان خط اول می‌گوید کدام است.

---

## ۱. ورود با گوگل

دکمه‌ی «ادامه با گوگل» همین الان توی صفحه‌ی ورود هست. تا وقتی تنظیم نشده،
خاکستری است و می‌نویسد «ورود با گوگل هنوز تنظیم نشده».

۱. برو به <https://console.cloud.google.com/apis/credentials>
۲. **Create credentials** → **OAuth client ID** → **Web application**
۳. توی **Authorized redirect URIs** این را اضافه کن — دقیقاً، حرف به حرف:

   ```
   https://دامنه‌ات/api/auth/google/callback
   ```

   گوگل این رشته را عیناً مقایسه می‌کند. یک `/` اضافه‌ی آخر، یا `http` جایی که
   سایت `https` سرو می‌شود، خطای `redirect_uri_mismatch` می‌دهد و هیچ چیز دیگری
   نمی‌گوید.

۴. **Client ID** و **Client secret** را بردار و توی متغیرهای لیارا بگذار:

   | متغیر | مقدار |
   |---|---|
   | `GOOGLE_CLIENT_ID` | همان Client ID |
   | `GOOGLE_CLIENT_SECRET` | همان Client secret |

`GOOGLE_REDIRECT_URI` را دست نزن مگر اینکه کار نکرد — برنامه آدرس را از خود
درخواست می‌سازد و معمولاً درست است. اگر پشت پراکسی اشتباه ساخت، همان آدرس بالا را
عیناً توی این متغیر بگذار.

### اگر `Error 400: redirect_uri_mismatch` گرفتی

یعنی رشته‌ای که برنامه فرستاد با هیچ‌کدام از رشته‌هایی که توی Google Console ثبت
کرده‌ای مو‌به‌مو یکی نیست. گوگل نمی‌گوید چه فرستاده شده — پس برنامه خودش می‌گوید.

**این آدرس را توی مرورگر باز کن:**

```
https://سایتت/api/auth/google/redirect-uri
```

یک خط برمی‌گرداند، همان چیزی که برنامه واقعاً به گوگل می‌فرستد. کپی کن و توی
Google Console بچسبان. حدس نزن — همین را بردار.

اگر باز هم نشد، به ترتیب احتمال:

| علت | نشانه |
|---|---|
| توی **Authorized JavaScript origins** چسبانده‌ای، نه **Authorized redirect URIs** | هر دو توی همان صفحه‌اند. کادر اول اصلاً `/path` قبول نمی‌کند — اگر آدرس با مسیر را رد کرد، یعنی کادر اشتباهی است |
| فقط دامنه را زده‌ای، بدون مسیر | `https://buddyai.liara.run` به جای `.../api/auth/google/callback` |
| یک `/` اضافه ته آدرس | `.../callback/` با `.../callback` یکی نیست |
| `http` نوشته‌ای ولی سایت `https` سرو می‌شود | |
| دامنه‌ی اختصاصی را ثبت کرده‌ای ولی روی `.liara.run` تست می‌کنی | یا برعکس. هر دو را ثبت کن |
| هنوز اعمال نشده | گوگل چند دقیقه (گاهی بیشتر) طول می‌دهد تا تغییر یک OAuth client را اعمال کند |

### دیواری که بعدش می‌خوری

اگر OAuth client روی حالت **Testing** بماند، فقط حساب‌هایی که خودت به عنوان
test user اضافه کرده‌ای می‌توانند وارد شوند؛ بقیه رد می‌شوند. توی صفحه‌ی
**OAuth consent screen** وضعیت را بگذار روی **In production**.

این برنامه فقط `openid`، `email` و `profile` را می‌خواهد — همان سه تای پایه و
غیرحساس. برای اینها گوگل بررسی و تأیید (verification) نمی‌خواهد، پس منتشرکردن
هیچ مراحل اضافه‌ای ندارد.

### یک نکته که عمدی است

اگر کسی قبلاً با همین ایمیل و رمز حساب ساخته باشد و بعد با گوگل وارد شود، دو حساب
فقط وقتی یکی می‌شوند که گوگل بگوید آن ایمیل را **تأیید کرده** است. وگرنه برنامه
جلویش را می‌گیرد و می‌گوید با رمز وارد شود. ایمیل تأییدنشده چیزی است که طرف
خودش تایپ کرده، و پذیرفتنش یعنی هر حسابی که ایمیلش قابل حدس باشد قابل گرفتن است.

## ۲. ایمیل خوش‌آمد با کد تخفیف

هر کسی که ثبت‌نام کند، یک کد تخفیف ۱۰٪ مخصوص خودش می‌گیرد و همان لحظه برایش
ایمیل می‌شود. کد فقط روی همان حساب کار می‌کند و تا ۳۰ روز اعتبار دارد.

ایمیل به زبان صفحه‌ای که طرف توی آن ثبت‌نام کرده فرستاده می‌شود — کسی که فارسی
می‌خوانده، ایمیل فارسی با عدد فارسی می‌گیرد.

متغیرها:

| متغیر | مقدار |
|---|---|
| `SMTP_HOST` | سرور ایمیلت، مثلاً `smtp.liara.ir` |
| `SMTP_PORT` | `587` (یا `465` اگر سرویس‌ات این را می‌خواهد) |
| `SMTP_USER` | آدرس صندوقی که ازش می‌فرستی |
| `SMTP_PASS` | رمزش |
| `SMTP_FROM` | آدرس فرستنده، اگر با `SMTP_USER` فرق دارد |

### قبل از اینکه کسی ثبت‌نام کند، تستش کن

```
node scripts/send-test-email.js you@example.com fa
```

یک ایمیل واقعی می‌فرستد، بدون اینکه حسابی بسازد یا کد تخفیف واقعی خرج کند. اگر
سرور ایمیل قبول نکرد، دلیلش را همان‌جا چاپ می‌کند.

**اگر ایمیل رفت ولی به spam خورد:** تقریباً همیشه به خاطر `SMTP_FROM` است —
صندوقی که از طرف دامنه‌ای می‌فرستد که مالکش نیست. آدرس فرستنده را روی دامنه‌ی
خودت بگذار.

### چرا SMTP، نه سرویس آماده

سرویس‌های ایمیل خارجی (SendGrid، Mailgun و…) از سرور ایران در دسترس نیستند.
SMTP ساده با هر سرویسی کار می‌کند، از جمله سرویس ایمیل خود لیارا.

---

## اگر هیچ‌کدام تنظیم نشود

هیچ چیزی خراب نمی‌شود. دکمه‌ی گوگل خاکستری می‌ماند و ثبت‌نام با ایمیل و رمز سر
جایش است؛ کد تخفیف ساخته و ذخیره می‌شود، فقط ایمیل نمی‌شود. ثبت‌نام هیچ‌وقت
منتظر سرور ایمیل نمی‌ماند — سرور ایمیلی که حالش بد است نباید حساب کسی را از بین
ببرد.
